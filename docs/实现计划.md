# 千千串口助手：皮肤映射与实现计划

日期：2026-09-22。项目：千千串口助手。参考实现：千千静听 C++ 复刻版。

本文保留最初设计目标。2026-09-22 已实现可运行的 C# / WPF 首版，当前功能与边界以根目录 README.md 和 docs/首版验证.md 为准。波形数据来自串口上传的数值，例如单片机 ADC 数据。

实际实现调整：波形使用 WPF 自绘及按像素 min/max 包络，UI 约 20 FPS；串口使用单一后台所有者线程读取和写入；主面板复用原图，辅助面板采用匹配主题的 WPF 布局。尚未完成全部阶段验收，尤其是真实串口、全 DPI、长时间高吞吐、九宫格吸附和 P4 示波能力。下文的 ScottPlot、MVVM 和完整辅助窗体等属于原计划，而非已实现声明。

## 1. 技术决策

**基于 .NET 学习与长期维护目标，原计划采用 C# + .NET 10 LTS + WPF + System.IO.Ports + ScottPlot 5。** 目标框架使用 `net10.0-windows`。Qt 在直接复用旧代码上占优；C# 更符合本项目的学习和长期维护目标。

| 评价项 | Qt / C++ | C# / WPF |
| --- | --- | --- |
| 现有项目复用 | 可提取 SkinParser、SkinEngine、图片滑块和精灵状态处理 | 位图可复用，解析、绘制、坐标、窗口逻辑需移植或桥接 |
| 原版 SKN 兼容 | 与现有技术一致，便于修正后复用 | 技术上可实现，但会新增一套兼容实现 |
| 普通串口工具开发 | Qt SerialPort 提供枚举、收发、参数、错误接口 | System.IO.Ports 也能实现；熟悉 C# 时表单开发方便 |
| 波形绘制 | 自绘 Widget 容易与像素皮肤混合 | WPF 自绘或图表库也胜任；不能仅凭语言判断性能 |
| 平台 | 可继续扩展到其他桌面系统，仍需逐平台测试 | 此处比较的 WPF 只运行在 Windows；不等于 C# 本身只能用于 Windows |
| 本项目总工作量 | 主要是修好兼容层并增加串口业务 | 除业务之外，还要移植已有皮肤框架 |

两条路线都可以做原版 SKN。C# 需要移植解析与呈现代码，但不需要重新设计文件格式，也不需要转换或重画全部皮肤。直接以现有 C++ 解析器、原始素材和这次盘点作为格式参考及对照用例。

第一版使用 WPF：皮肤主面板用 Canvas 定位，图片状态用 CroppedBitmap 与 ControlTemplate，日志与参数面板用 Grid 和标准控件模板。轻量 MVVM 分离会话状态与界面，可采用 CommunityToolkit.Mvvm；初期不搭建复杂插件/依赖注入框架。大波形先集成 ScottPlot.WPF，统一背景、刻度、网格、曲线和字体，再按实际性能优化。主面板的小波形可使用 DrawingVisual/OnRender。采样、触发和时间轴不依赖图表库。

不建议第一版通过 C++/CLI 或 P/Invoke 包装旧 Qt 皮肤引擎：它依赖 QString/QPixmap/QObject，桥接会带来双运行时、图像转换和部署工作，对学习单一 .NET 技术栈帮助有限。

环境检查记录：参考项目采用 Qt 6.10.3 与 MinGW 13.1，已安装 Qt SerialPort。初始 .NET 环境具有 Visual Studio Community 2026（18.7.3）、VS Code 和 .NET 10.0.0 运行时，尚缺少 SDK 与 ManagedDesktop 工作负载。同日已补齐“.NET 桌面开发”、.NET SDK 10.0.301、WindowsDesktop 10.0.9 和 Blend；命令行、VS MSBuild 构建及 WPF 运行验证通过，安装器未要求重启。详见 `environment/环境配置与验证.md`。

官方资料：[QSerialPort](https://doc.qt.io/qt-6/qserialport.html)、[Qt Charts](https://doc.qt.io/qt-6/qtcharts-index.html)、[Qt Graphs](https://doc.qt.io/qt-6/qtgraphs-index.html)、[WPF 概览](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)、[SerialPort.DataReceived](https://learn.microsoft.com/en-us/dotnet/api/system.io.ports.serialport.datareceived)。

.NET 选型资料：[.NET 支持周期](https://dotnet.microsoft.com/en-us/platform/support/policy)、[ScottPlot WPF 接入](https://scottplot.net/quickstart/wpf/)、[ScottPlot 实时数据](https://scottplot.net/cookbook/5/LiveData/DataStreamerQuickstart/)。.NET 10 为当前 LTS，官方支持至 2028-11-14。Qt Charts 自 Qt 6.10 起弃用，若后续回到 Qt 路线则重新评估 Qt Graphs 或自绘。

### C++ 到 C# 的迁移对应

| 现有模块 / 类型 | .NET 实现 | 复用方式 |
| --- | --- | --- |
| `SkinParser` 的 ZIP 解包 | `System.IO.Compression.ZipArchive` | 复用读取目标与测试样本，不移植简化 ZIP 算法 |
| XML 与编码 | `XmlReader/XDocument` + 兼容词法层 + `CodePagesEncodingProvider` | 优先 BOM/声明与严格 UTF-8，失败按已知旧编码回退；ZIP 文件名编码和 XML 正文编码分别处理 |
| `SkinConfig/SkinWindow/SkinElement` | C# records/classes，矩形使用独立数据类型 | 保留原字段，补齐未知属性与窗口；解析层不依赖 WPF |
| `SkinEngine` | `SkinService` + 不可变 `SkinDocument` + 图片缓存 | 保留加载/切换/查询责任；新皮肤验证成功后交换 |
| `QPixmap` / 精灵图 | `BitmapSource` / `CroppedBitmap` | 原 BMP 和 SKN 原样使用；透明色转换为 alpha |
| 图片按钮 / 滑块 | WPF 自定义模板控件 | 原状态图对应 Normal/Hover/Pressed/Disabled；滑块逻辑不和串口参数耦合 |
| Qt 信号与槽 | C# events、ICommand、属性通知 | 状态通过 ViewModel 驱动；UI 更新回到 Dispatcher |

学习顺序：读取 SKN（文件/集合/XML/异常）→ 图片窗口（XAML/布局/控件模板）→ 串口收发（事件/线程/资源释放）→ ViewModel（绑定/命令）→ 波形缓冲（数组/性能）→ 单元测试与发布。每一步都产生可运行结果。

## 2. 本地资产盘点与已发现的问题

对全部 69 个 `.skn` 做 ZIP/CRC、编码探测、严格 XML 解析和标签盘点，详细结果在 `skin-inventory.json`。盘点使用 Python 标准 XML 解析器，不是 Qt 运行时兼容测试；严格 XML 失败不等于原版播放器不能打开。

| 项目 | 数量 / 结论 |
| --- | --- |
| ZIP 可读 | 69 / 69，未报告 CRC 错误 |
| UTF-8 可解码 | 16 |
| UTF-8 失败、GB18030 可解码 | 53 |
| 解码后严格 XML 通过 | 34 |
| 严格 XML 失败 | 35；已看到未加引号的属性值等旧格式写法 |
| 主窗口 / 歌词窗口 / 播放列表窗口 | 各 69 |
| 均衡器窗口 | 64 |
| 迷你窗口 | 62 |
| 浏览器窗口 | 33 |
| 播放 / 暂停 / 上一项 / 下一项 | 各 69 |
| 停止按钮 | 60 |
| 打开按钮 | 58 |

已经阅读 `src/skinparser.*`、`src/skinengine.*`、`src/mainwindow.cpp`、内置 Purple XML，并提取经典皮肤、iBlue、HiFi 3.1 的实际素材。三个主窗口原始尺寸分别为 268×165、328×135、275×116。

必须在移植时处理的具体问题：

1. `parseSkinXml()` 固定调用 `QString::fromUtf8()`，不能正确处理上述非 UTF-8 内容。
2. 旧包存在严格 XML 不接受的写法。建立有边界的兼容词法处理，对已知缺引号、裸 `&` 等情况分类；保留源字节和诊断。不能用一次全局正则替换冒充通用 XML 修复。
3. 当前结构只显式保存四类窗口，缺少 mini/browser；解析过程也没有完整按结束标签恢复窗口上下文，未知窗口中的元素可能进入上一窗口。改为明确的窗口栈或按子树解析，未知节点跳过。
4. 原版辅助 XML 使用 `Lyric`、`PlayList`、`TextColor`、`HilightColor`、`Color_Text` 等名称，现有歌词/列表解析并未完整覆盖。颜色、字体和大小写均需要兼容。
5. 当前换肤先 `unload()` 再加载，失败会丢失旧资源；应预加载并验证成功后一次替换。
6. 当前皮肤坐标、默认 Purple 回退、圆角处理与播放器业务混在 MainWindow 中。不能把同一组坐标、按钮圆角或背景裁切应用到所有皮肤。
7. ZIP 读取需要完整性、路径边界、解压大小与图片尺寸检查；当前实现存在直接拼接归档路径、解压失败仍写数据等情况，应作为读取层正确性一起修正。

## 3. 产品布局：保留千千静听的组合小窗口

默认桌面组合：左上主控制器、左下串口终端、右侧较大的波形窗口；通道控制面板按需贴在波形下方。支持边缘吸附、组合移动、独立隐藏、位置保存和迷你模式。

| 原皮肤窗口 | 新功能 | 布局策略 |
| --- | --- | --- |
| `player_window` | 串口连接与监视控制 | 保留原主面板几何比例与精灵图片；显示 COM、连接状态、运行时长、小波形 |
| `playlist_window` | RX/TX 日志、发送编辑器、命令预设 | 沿原 `resize_rect` 扩展客户区；日志、发送、预设用标签切换，避免三块同时挤在小面板 |
| `lyric_window` | 主波形示波器 | 原边框和标题栏可伸展，中央留出有刻度的绘图区，工具栏独立布局 |
| `equalizer_window` | 通道显示、量程、偏移、触发设置 | 保留外框与滑块风格；选中通道后编辑 gain/offset；高级选项放折叠区 |
| `mini_window` | COM、状态、RX/TX 活动、恢复主界面 | 缺失时用同主题简化条，不能从上一窗口误取元素 |
| `browser_window` | 后续扩展的协议/会话工作区 | 可选，不让基础功能依赖它 |

建议应用默认尺寸以逻辑像素计算：主面板按原尺寸×可选 UI 倍率；终端至少约 420×300；波形至少约 560×360。小屏幕允许各窗独立摆放。示意中的窄屏堆叠用于阅读方案，桌面程序仍采用真实独立窗口。

## 4. 主面板的统一功能映射

所有皮肤使用同一套动作 ID，换肤不能改变功能含义。

| SKN 元素 | 串口助手动作 / 显示 | 交互边界 |
| --- | --- | --- |
| `play` / `pause` | 开始监视 / 冻结显示 / 恢复显示 | 未连接时开始会按当前配置打开端口；冻结只停界面刷新，后台接收与录制继续 |
| `stop` | 结束会话、断开串口 | 同时停止周期发送；没有 stop 的皮肤在公共菜单与端口面板提供明确的“断开”入口 |
| `prev` / `next` | 选择上/下一条发送预设 | 只选择、填入编辑器，不立即发送，防止误发控制命令 |
| `open` | 端口与通信参数 | COM、波特率、数据位、停止位、校验、流控；缺失时公共菜单提供同一入口 |
| `playlist` | 显示 / 隐藏串口终端 | 内容为收发日志和发送区 |
| `lyric` | 显示 / 隐藏波形窗口 | 对应原 LRC 按钮，悬停提示显示新含义 |
| `equalizer` | 显示 / 隐藏通道设置 | 缺失时也可从波形工具栏打开 |
| `mute` | 开关错误提示音 | 避免把“静音”误当停止接收；无声音配置时禁用 |
| `progress` | 采集历史定位 | 拖动进入历史查看，明确显示 LIVE/HOLD；一键回到实时 |
| `volume` | 波形可见时间跨度 | 与波形窗口 Time/div 同步；显示秒/毫秒单位，不映射到波特率 |
| `info` | COM 与协议摘要 | 例如 `COM3 · 115200 · 8N1`；不足时缩短为 `COM3 · 115200`，完整值在提示中 |
| `status` | LIVE / HOLD / OFF / ERROR | 中文完整状态在终端；短字不挤占位图 |
| `stereo` | 解析到的通道数 | 例如 `4 CH`；没有该元素时放波形栏 |
| `led` | 会话时长 | 数码管字库只显示支持的字符；超时溢出采用小时/分模式，完整时间在提示中 |
| `visual` | 当前选中通道的小波形 | 默认不做音乐频谱动画；有原始数据才绘制 |
| `minimode` / `minimize` / `exit` | 迷你模式 / 最小化 / 退出 | 操作语义保持一致；关闭附属窗只隐藏，不断开连接 |
| `icon`、主窗右键菜单 | 通用功能入口 | 皮肤、连接/断开、窗口、日志、导入导出与设置；所有皮肤都能访问 |

串口参数使用可阅读的下拉框和输入框，放在端口面板。不能把 9600、115200 等离散参数机械地塞进 EQ 滑块。周期发送间隔用带单位的数值框，滑块只用于视觉缩放或通道偏移。

## 5. 保证外观一致的方法

### 5.1 三层适配

`原始 SKN 数据 → 标准 SkinDocument → SerialSkinAdapter → 控件与绘制`

- 原始文件只读加载，保留作者与原素材；不修改导入的 `.skn`。
- 标准层保存原始 L/T/R/B 矩形、图片状态、透明色、字体、颜色、窗口尺寸、resize 和 align 规则。宽高由右下坐标减左上坐标得到。
- 语义层只映射角色：Connect/Monitor、Terminal、Scope、Channels 等，与串口对象解耦。
- 通过皮肤内容哈希定位小型适配配置，明确文字遮罩、可用标题区、特殊伸缩和状态图切片；包名/作者仅用于展示，不能成为唯一匹配条件。

### 5.2 位图细节

- 主面板保持比例；非矩形透明边缘沿原透明色/alpha 处理。原图里的装饰线与按钮不做随意圆角。
- 附属窗按 `resize_rect` 做九区域伸缩/平铺，角部和标题图标保持尺寸。必须区分“背景模板尺寸”与 XML 中声明的窗口尺寸，例如经典歌词背景只有 268×60，但窗口声明为 268×165。
- 精灵状态数量与方向由图片尺寸、控件尺寸和已知适配信息确定；不能所有文件无条件横向四等分。
- 皮肤中写死的“31、62、125Hz”等 EQ 文字无法自动变成串口参数。重点皮肤用明确的同色内容底板替换客户区，再布置通道控件；普通皮肤使用一致的主题控件。绝不在原字上叠一层新字。
- 图片按钮可以保留原图；PL/LRC/EQ 等文字优先在适配模式替换为“收发/波形/通道”。忠实原皮肤模式保留原文字并提供清晰的提示及快捷入口。绘制在背景里的品牌文字也通过已知适配区域处理，无法可靠处理时保留原图而不硬盖。
- 颜色从辅助 XML 取值，并生成绘图区、网格、文字、选中项主题。曲线通道色独立保持辨识度；同一通道跨皮肤保留自定义配置和线型。
- 收发区使用等宽字体，数值编辑器保证可读；装饰字体仅用于标题、摘要。使用字体测量和省略号，不靠不断缩小字号塞入长文本。
- 100%、125%、150%、200% DPI 分别检查，坐标和命中区域采用同一变换；SKN 基准像素映射到 WPF DIP 后叠加可选 UI 倍率，避免系统 DPI 与手工缩放重复计算。无边框窗优先保持不透明客户区，仅在确有异形外轮廓时启用对应透明处理，并验证图表合成性能。

### 5.3 兼容等级与验收

- **A级精调**：经典皮肤、iBlue、HiFi 3.1，加内置 Purple 作回退。全部窗口、状态、缩放、文字与伸缩截图人工检查。
- **B级兼容**：其他皮肤载入、主面板与功能完整；需要通用控件回退的窗口在皮肤管理器注明。
- **C级诊断**：无法可靠解析或关键资源缺失时保留当前皮肤并说明原因。不能宣称所有 69 个未经视觉验收就已经完美支持。

重点视觉验收：无重叠和裁字、按钮三/四态正确、透明边缘无粉边、图与点击位置一致、日志/波形扩展后角部不变形、所有关键功能都有入口。换肤保持串口、采样、缓存、发送配置与窗口逻辑状态。

## 6. 串口与波形功能范围

### 第一版必须可用

- 单串口打开/关闭、手动刷新设备列表、热拔插错误反馈、参数保存。
- 文本/HEX 收发、时间戳、换行策略、计数、清屏、日志保存。
- 命令预设与周期发送；输入合法性检查、发送队列上限、断开即停止。设备重新连接后周期发送不自动启动。
- 1–8 通道数值曲线，显隐、时间范围、Y 轴自动/手动量程、平移缩放、冻结/恢复、历史查看。
- 原始字节日志与解析数值记录分离；数值导出 CSV。点击导出按钮后选择目标文件并保存。
- 第一种协议为换行分帧的数值行：`1.23,2.34,3.45\r\n`；允许配置分隔符、通道数和字段映射。日志文本不能无条件当波形数据。
- 时间轴优先采用设备时间戳；无时间戳时可输入固定采样率，用样本序号推算时间；仅有电脑到达时间时标记为“到达时间”，不用它宣称精确频率。
- 每通道保存名称、单位、比例与偏移：`工程量 = 原始值 × scale + offset`。ADC→电压的 Vref、位数、分压/增益由设备配置提供，不作固定假设。

### 第二阶段示波器能力

- 上升沿/下降沿触发、阈值、Auto/Normal/Single、预触发缓存。
- 两个测量游标、Δt/ΔV、Min/Max/Mean/RMS；频率测量在有效采样时间基础上计算。
- 二进制帧：同步标识、长度、序号、设备时间、通道数据和校验；具体布局与固件协商后冻结。
- 录制回放、会话配置；需要时增加协议插件，例如具体版本的 VOFA 兼容格式，届时按其官方格式验证。
- FFT 为后续选项：基于原始等间隔数值、实际采样率和窗口函数计算；旧播放器的 A 计权、动态归一化、平滑频谱条不可直接当测量工具使用。

这是串口数值示波显示器。模拟采样的采样率、量程、精度与模拟带宽由单片机 ADC、前端电路、固件和传输决定。

### 吞吐预算示例

8N1 下每字节约占 10 bit，因此 115200 baud 理想上限约 11,520 B/s。若每个采样时刻上传 4 个 uint16 通道，无帧开销上限为 `11520 / 8 = 1440` 组/s，即每通道 1440 sample/s；协议开销、设备与驱动会继续降低实际速率。ASCII 数字通常占用更多字节。四通道各 10 ksample/s、16 位仅有效数据就需要 80,000 B/s，即至少约 800 kbaud（仍未含帧开销）。

“界面每秒刷新 30 次”与“每通道每秒采集多少点”是两个参数，必须分开。

## 7. 数据与线程架构

```text
后台串口服务：SerialPort + TxScheduler → 增量字节缓冲 → FrameParser
                                      ├→ 原始记录队列 → 文件写入线程
                                      └→ SampleBatch → 有界样本环形缓冲
                                                        ├→ 数值记录队列
                                                        └→ UI 定时取快照（约 30 FPS）
                                                            → 每像素 min/max 包络
                                                            → ScottPlot.WPF
UI：WPF SkinnedWindow + ViewModel + 主面板/终端/波形/通道
```

- SerialPort 的打开/关闭/写入由后台服务串行管理；接收采用单一策略，初期可用 DataReceived 读取并推送到有界队列，不能与另一读循环同时抢读。事件线程不操作 WPF 控件，UI 通过 Dispatcher 批量取快照。退出与热拔插处理事件解绑、正在进行的读取以及 Dispose 竞态。
- DataReceived 不保证逐字节触发，也不等于完整帧，必须支持拆包、粘包、半行、无效数字、错误长度、CRC 失败和重同步。
- 每通道环形缓冲有容量/时长上限。可见历史滚出范围属于正常淘汰；队列溢出属于丢数，分别计数。发生丢帧或时间跳变时断开曲线，避免伪造连续性。
- UI 只批量刷新文本，限制日志可见行数；不要每收到一个字节就增加一个控件或刷新图表。
- 显示降采样用每像素区间 min/max 保留尖峰；触发、统计和记录使用原始样本。缩放到少量样本时显示原始点。
- 文件写入队列也必须有界；不能用无限缓存掩盖磁盘跟不上。发生记录错误要明确显示并停止录制或标记丢数。
- 关闭、热拔插、切皮肤、切窗口由独立状态机管理。暂停显示与暂停/停止设备采样分开；应用不能自行假定单片机支持停采命令。

建议新项目目录：

```text
src/TTSerial.App/      WPF Views、ViewModels、皮肤控件、ScottPlot 适配
src/TTSerial.Core/     皮肤解析、FrameParser、RingBuffer、TriggerEngine
src/TTSerial.IO/       SerialPortService、TxScheduler、Recorder
resources/            内置回退主题
skin-adapters/        重点皮肤配置
tests/TTSerial.Tests/  解析器、串口模拟、波形算法、皮肤用例
docs/                 本计划、静态盘点、协议规格和验收记录
```

P0/P1 是第一个可评审里程碑，P2/P3 构成第一版实用工具。不要在所有皮肤完全精调之前阻塞串口核心，但不能绕过基础解析正确性。

拟定性能验收目标（不是当前实测结果）：在本机以模拟数据喂入 8 通道、各 10 ksample/s，持续 30 分钟，显示约 30 FPS，内存保持设定上限，采集数据不因冻结界面而丢失；真实串口按适配器和设备可持续速率另行测量。模拟吞吐目标不能直接当 UART 硬件能力宣传。

## 9. 下次实现前仍需落地的设备参数

无需阻塞皮肤基础工作。接入设备时确定：具体行/二进制协议、通道数量、单位、采样率、是否有设备时间戳、ADC 换算关系、可用串口速率。首版先采用数值行协议、最多 8 通道和显式单位配置。
